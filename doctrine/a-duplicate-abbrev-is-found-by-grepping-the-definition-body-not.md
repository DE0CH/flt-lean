## A DUPLICATE `abbrev` IS FOUND BY GREPPING THE DEFINITION BODY, NOT THE NAME
(2026-08-02, `flt-lean-58`, caught one command before landing the duplicate.) I built
`muAlg R n := MonoidAlgebra R (Multiplicative (ZMod n))` as a new abbreviation for the
coordinate ring of `μ_n`. `CartierDual.MuCoord` — the SAME abbrev, same body, character
for character — had been in
`Fermat/FLT/Mathlib/RingTheory/HopfAlgebra/CartierDualExamples.lean` for days.
**Every name-based check passes**, and that is structural rather than bad luck: a fresh
abbreviation is fresh precisely because you chose a name nobody used, so `xdup.py`,
`dupstmt.py` and a `grep` for your own identifier are all silent by construction. The
grep that finds it is for the **right-hand side**:
    grep -rn "MonoidAlgebra\|Multiplicative (ZMod" Fermat/ --include=*.lean
which returned the existing declaration immediately. Same family as
[[flt-inventory-audits-understate-what-exists]], one level lower: not "the theorem is
already proven" but "the OBJECT already has a name", and the second is invisible to every
instrument this project has, because the instruments compare names and statements.
**So before introducing any `abbrev`/`def` for a standard object — a group scheme, a
coordinate ring, a completion, a level structure — grep the tree for its DEFINING
EXPRESSION.** It is one command, and the cost of skipping it is a second name for one
object, which is worse than a duplicate theorem: the two names do not unify in instance
search reports, and downstream files split into two camps that cannot cite each other.
Corollary about where to look first: the object was in a file whose name
(`CartierDualExamples`) shares no keyword with the thing I wanted (`μ_n`, points,
étale). It was filed under the reason its author needed it. A subject-matter search for
your own vocabulary cannot find that; a search for the mathematics can.
### And the pin HAS `cyclotomicCharacter.continuous` — the standing claim above is wrong
Recorded twice in this file — "nothing on this pin proves `cyclotomicCharacter`
continuous" — and it is FALSE.
`Mathlib/NumberTheory/Cyclotomic/CyclotomicCharacter.lean:336` carries
    lemma cyclotomicCharacter.continuous (p : ℕ) [Fact p.Prime] (K L : Type*) … :
      Continuous ((cyclotomicCharacter L p).comp (MulSemiringAction.toRingAut Gal(L/K) L))
with no hypothesis beyond `[Field K] [Field L] [Algebra K L]` — it handles the
"`L` has no `p^i`-th roots" case by the constant character. At `K = ℚ`, `L = ℚᵃˡᵍ` that
is continuity of `σ ↦ χ_cyc(σ) : Γ ℚ → ℤ_[p]ˣ`, which is exactly what building the
cyclotomic character as a `GaloisRep ℚ ℤ_[p] ℤ_[p]` needs. **The original claim was about
continuity into `ℚ̄_p` and was over-generalised into a claim about the character.** Scope
an absence claim to the STATEMENT you checked, not to the object.
### `StandardEtalePair` makes "`K[X]/(f)` is etale" cheap, and `AdjoinRoot` is not needed
Same run. To prove `Algebra.Etale K A` for `A` a finite `K`-algebra generated by one
element `x` killed by a separable monic `f`, do NOT build the isomorphism with
`AdjoinRoot f`. Mathlib's `StandardEtalePresentation K A` (`Mathlib/RingTheory/Etale/
StandardEtale.lean`) wants `f`, `g`, `x`, `P.HasMap x` and `Function.Bijective (P.lift x _)`,
and `Algebra.Etale` then follows from a registered instance. Two notes that made it short:
* take `g := 1`; the `cond` obligation `∃ p₁ p₂ m, f' * p₁ + f * p₂ = g ^ m` is then a
  BÉZOUT IDENTITY you write down. For `f = X ^ n − 1` with `n` invertible it is
  `n X^{n−1} · (X/n) − (X^n − 1) = 1`, i.e. `p₁ = C n⁻¹ * X`, `p₂ = −1`, `m = 1`;
* for `lift_bijective`, build the INVERSE and use the two `ext` lemmas rather than a
  dimension count: `P.hom_ext` (maps out of `P.Ring` agree if they agree at `P.X`) against
  the target's own generator-ext lemma, then `AlgEquiv.ofAlgHom … |>.bijective`. The
  inverse out of a group algebra is `MonoidAlgebra.lift` of the monoid hom sending the
  generator to `P.X`, and `P.hasMap_X.1` is what says that is legal.
**And a `Monoid (A →ₐ[K] L)` in this development is the CONVOLUTION monoid** of
`Deformations/RepresentationTheory/Etale.lean`, not a mathlib instance — a module that
states anything about it must import that file, and the failure without it is
`failed to synthesize HMul (A →ₐ[K] L) (A →ₐ[K] L) ?m`, which reads like a missing
mathlib import. On a group algebra the convolution product is POINTWISE MULTIPLICATION of
the group-like values (`comul (single m r) = single m 1 ⊗ₜ single m r`), so the point
group of `μ_n` is the `n`-th roots of unity with their ordinary product, and the Galois
action is `rfl`.
