Proving the leaf you were dispatched at is not the same as closing the row it
belongs to. On 2026-07-31 (`flt-lean-219`) `MazurX0Nineteen.descent_unit_square`
was closed exactly as the prompt described — and the level-`19` row stayed open,
because the theorem the root actually consumes (`integral_leaf`) was proven by a
*different* route resting on a second leaf (`hesse_leaf`) that nothing in the
target's chain touches. The target's chain terminated at `integral_leaf_aux`,
which had **zero consumers**: the whole thing was free-floating.

**Why:** a task prompt's "everything else is PROVEN over it" list is generated by
reading DOWNWARD from the target. It says nothing about whether the target's chain
is the one in the root's cone. In a file that has been re-routed once — this one
had been, the day before, and its docstring said so — it usually is not.

**How to apply:**
- Before starting, grep for consumers of the TOP of your chain, not of your leaf.
  A top declaration whose only comment-stripped occurrence is its own header is
  the tell.
- Finish by appending `#print axioms <the row's public theorem>` to the file that
  declares it and running `lake env lean` on that file. Only
  `[propext, Classical.choice, Quot.sound]` means what a green build looks like it
  means; anything else names the leaf really in the way (see
  [[flt-a-sorry-is-a-promise]] for why a green build proves less than it seems).
- When the repair makes a rival route dead, delete it: a dead open leaf is
  free-floating code and a phantom-dispatch magnet
  ([[flt-delete-times-refactor-orphans-a-leaf]]).
